# สัปดาห์ 9: Live Dashboard, Cache และ Streaming

โปรเจกต์ประจำคาบคือ **Live Dashboard** ที่มี Static shell, ข้อมูลสรุปที่ Cache ได้ และ Widget แบบ Dynamic ที่ Stream เข้ามาทีละส่วน

## ผลลัพธ์การเรียนรู้

- มองเห็นและแก้ Data Waterfall
- Fetch หลายแหล่งพร้อมกันด้วย `Promise.all`
- ใช้ `<Suspense>` กำหนด Streaming boundary
- แยก Static, Cached และ Dynamic content
- ใช้ Cache Components, `'use cache'`, `cacheLife` และ `cacheTag`

## 1. เปิด Cache Components

แก้ `next.config.ts`

```ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  cacheComponents: true,
}

export default nextConfig
```

เปิด Development Server ใหม่หลังแก้ Config

<Callout type="info">
  บทนี้ใช้ Cache Components ของ Next.js 16 ขึ้นไป หากสอนเวอร์ชันเก่า ให้แยกเอกสารเรื่อง caching ตามเวอร์ชัน อย่านำตัวอย่าง `unstable_cache` รุ่นเก่ามาปะปนกับ `'use cache'`
</Callout>

## 2. Cached Stats และ Parallel Fetching

สร้าง `src/lib/dashboard.ts`

```ts
import 'server-only'
import { cacheLife, cacheTag } from 'next/cache'

type JsonPlaceholderItem = {
  id: number
}

async function fetchCount(path: string) {
  const response = await fetch(`https://jsonplaceholder.typicode.com/${path}`)
  if (!response.ok) throw new Error(`โหลด ${path} ไม่สำเร็จ`)
  const items = (await response.json()) as JsonPlaceholderItem[]
  return items.length
}

export async function getDashboardStats() {
  'use cache'
  cacheLife('hours')
  cacheTag('dashboard-stats')

  const [users, posts, todos] = await Promise.all([
    fetchCount('users'),
    fetchCount('posts'),
    fetchCount('todos'),
  ])

  return { users, posts, todos }
}
```

ตัวอย่างที่ไม่ควรทำ:

```ts
const users = await fetchCount('users')
const posts = await fetchCount('posts')
const todos = await fetchCount('todos')
```

รูปแบบนี้รอทีละ Request ทั้งที่ไม่พึ่งกัน เรียกว่า Sequential Waterfall

## 3. Cached Widget

สร้าง `src/components/stats.tsx`

```tsx
import { getDashboardStats } from '@/lib/dashboard'

export async function Stats() {
  const stats = await getDashboardStats()

  const cards = [
    { label: 'Users', value: stats.users },
    { label: 'Posts', value: stats.posts },
    { label: 'Todos', value: stats.todos },
  ]

  return (
    <section aria-labelledby="stats-title">
      <h2 id="stats-title" className="text-2xl font-semibold">Overview</h2>
      <dl className="mt-4 grid gap-4 sm:grid-cols-3">
        {cards.map((card) => (
          <div key={card.label} className="rounded-2xl border bg-white p-5">
            <dt className="text-sm text-slate-500">{card.label}</dt>
            <dd className="mt-2 text-3xl font-bold">{card.value}</dd>
          </div>
        ))}
      </dl>
    </section>
  )
}
```

## 4. Dynamic Widgets

สร้าง `src/components/live-clock.tsx`

```tsx
import { connection } from 'next/server'

export async function LiveClock() {
  await connection()
  await new Promise((resolve) => setTimeout(resolve, 1200))

  const now = new Intl.DateTimeFormat('th-TH', {
    dateStyle: 'full',
    timeStyle: 'medium',
    timeZone: 'Asia/Bangkok',
  }).format(new Date())

  return (
    <section className="rounded-2xl bg-slate-950 p-6 text-white">
      <h2 className="text-xl font-semibold">Server time</h2>
      <p className="mt-3 font-mono">{now}</p>
    </section>
  )
}
```

สร้าง `src/components/recent-activity.tsx`

```tsx
type Comment = {
  id: number
  name: string
  email: string
}

export async function RecentActivity() {
  await new Promise((resolve) => setTimeout(resolve, 1800))

  const response = await fetch(
    'https://jsonplaceholder.typicode.com/comments?_limit=5',
    { cache: 'no-store' },
  )

  if (!response.ok) throw new Error('โหลด Activity ไม่สำเร็จ')
  const comments = (await response.json()) as Comment[]

  return (
    <section className="rounded-2xl border bg-white p-6">
      <h2 className="text-xl font-semibold">Recent activity</h2>
      <ul className="mt-4 divide-y">
        {comments.map((comment) => (
          <li key={comment.id} className="py-3">
            <p className="font-medium">{comment.name}</p>
            <p className="text-sm text-slate-500">{comment.email}</p>
          </li>
        ))}
      </ul>
    </section>
  )
}
```

การหน่วงเวลาใช้เพื่อสังเกต Streaming ในห้องเรียน ไม่ควรใส่ใน Production

## 5. Suspense Boundaries

สร้าง `src/app/dashboard-live/page.tsx`

```tsx
import { Suspense } from 'react'
import { LiveClock } from '@/components/live-clock'
import { RecentActivity } from '@/components/recent-activity'
import { Stats } from '@/components/stats'

function CardSkeleton({ label }: { label: string }) {
  return (
    <div
      role="status"
      aria-label={`กำลังโหลด ${label}`}
      className="min-h-40 animate-pulse rounded-2xl bg-slate-200"
    />
  )
}

export default function DashboardPage() {
  return (
    <main className="mx-auto max-w-6xl px-5 py-12">
      <header className="mb-10">
        <p className="text-sm font-semibold text-indigo-700">Live system</p>
        <h1 className="mt-2 text-4xl font-bold">Dashboard</h1>
        <p className="mt-3 text-slate-600">
          Static shell ปรากฏก่อน แล้วแต่ละ Widget stream เข้ามา
        </p>
      </header>

      <Suspense fallback={<CardSkeleton label="สถิติ" />}>
        <Stats />
      </Suspense>

      <div className="mt-6 grid gap-6 md:grid-cols-2">
        <Suspense fallback={<CardSkeleton label="เวลา" />}>
          <LiveClock />
        </Suspense>
        <Suspense fallback={<CardSkeleton label="กิจกรรมล่าสุด" />}>
          <RecentActivity />
        </Suspense>
      </div>
    </main>
  )
}
```

หากใช้ Suspense boundary เดียวครอบทุก Widget หนึ่งส่วนที่ช้าจะทำให้ทุกส่วนรอพร้อมกัน การแบ่ง boundary ตามสิ่งที่ผู้ใช้รับรู้ช่วยให้ส่วนที่พร้อมแสดงก่อน

## Mental model

| ประเภท | ตัวอย่าง | พฤติกรรม |
| --- | --- | --- |
| Static | Heading, Navigation | Prerender ได้ทันที |
| Cached | Stats ที่เปลี่ยนไม่บ่อย | ใช้ `'use cache'` และ cache lifetime |
| Dynamic | Session, Cookie, เวลาปัจจุบัน | ประมวลผลต่อ Request และอยู่ใน Suspense |

ห้ามเรียก `cookies()`, `headers()` หรืออ่าน Search Params ภายใน `'use cache'` ให้ดึงค่าข้างนอกแล้วส่งเป็น argument เมื่อจำเป็น

## 6. Cache Invalidation

เมื่อ Mutation เปลี่ยนข้อมูลสถิติ:

```ts
'use server'

import { updateTag } from 'next/cache'

export async function refreshDashboardStats() {
  // ทำ mutation หรือ sync ข้อมูลจริงก่อน
  updateTag('dashboard-stats')
}
```

`updateTag` ทำให้ Request เดียวกันอ่านข้อมูลใหม่ทันที ส่วน `revalidateTag` เหมาะกับ stale-while-revalidate

## Lab และ Challenge

1. เปิด Network panel แล้ว Refresh เพื่อสังเกตลำดับ UI
2. เปลี่ยน Delay ของแต่ละ Widget
3. ทดลองรวม Suspense เป็น boundary เดียวแล้วเปรียบเทียบ
4. สร้าง Widget ใหม่จาก API อื่น
5. เพิ่ม `error.tsx` สำหรับ Dashboard

Challenge: เพิ่ม user-specific widget ที่อ่าน cookie ข้างนอก cached function และส่ง user ID เข้า function เป็น argument

## Definition of Done

- [ ] ไม่มี Sequential Waterfall ในงานที่ทำพร้อมกันได้
- [ ] Widget Dynamic มี Suspense fallback
- [ ] Skeleton มีขนาดใกล้เนื้อหาจริง ลด Layout Shift
- [ ] Cached function มี cache lifetime ชัดเจน
- [ ] ไม่อ่าน Runtime API ภายใน `'use cache'`
- [ ] Error จาก fetch ไม่ถูกกลืนเงียบ

## Exit ticket

1. `Promise.all` แก้ปัญหาอะไร
2. Suspense boundary ควรแบ่งตามหลักใด
3. Static, Cached และ Dynamic content ต่างกันอย่างไร
