# สัปดาห์ 6: Event Registration และ Server Actions

โปรเจกต์ประจำคาบคือฟอร์มลงทะเบียนกิจกรรมที่มี Validation ฝั่ง Server แสดงข้อผิดพลาดรายช่อง และปิดปุ่มระหว่างส่งข้อมูล

สัปดาห์นี้เปลี่ยนจาก “อ่านข้อมูล” เป็น “ส่งข้อมูลเพื่อให้ Server ทำงาน” แต่ยังไม่บันทึกฐานข้อมูลจริง เรื่อง Persistence จะอยู่ในสัปดาห์ 7

## ผลลัพธ์การเรียนรู้

- สร้าง Server Action ด้วย `'use server'`
- อ่าน `FormData` และ validate ข้อมูลที่เชื่อถือไม่ได้
- ใช้ `useActionState` รับผลลัพธ์จาก Server
- ออกแบบ Field error, Form error, Pending และ Success state
- อธิบาย Progressive Enhancement และความต่างจาก Route Handler

## โครงสร้าง

```text
src/app/register/
```

## 1. ออกแบบ State ที่ส่งกลับ

สร้าง `src/app/register/actions.ts`

```ts
'use server'

export type RegistrationState = {
  status: 'idle' | 'error' | 'success'
  message: string
  registrationCode?: string
  errors: {
    name?: string
    email?: string
    session?: string
    terms?: string
  }
  values: {
    name: string
    email: string
    session: string
  }
}

export const initialState: RegistrationState = {
  status: 'idle',
  message: '',
  errors: {},
  values: {
    name: '',
    email: '',
    session: '',
  },
}
```

State นี้เป็น plain object จึง serialize จาก Server กลับ Client ได้

## 2. เขียน Server Action และ Validation

เพิ่มต่อในไฟล์เดิม:

```ts
const sessions = ['morning', 'afternoon'] as const

function readText(formData: FormData, name: string) {
  const value = formData.get(name)
  return typeof value === 'string' ? value.trim() : ''
}

export async function registerForEvent(
  _previousState: RegistrationState,
  formData: FormData,
): Promise<RegistrationState> {
  const name = readText(formData, 'name')
  const email = readText(formData, 'email').toLowerCase()
  const session = readText(formData, 'session')
  const acceptedTerms = formData.get('terms') === 'on'

  const errors: RegistrationState['errors'] = {}

  if (name.length < 2) {
    errors.name = 'กรุณากรอกชื่ออย่างน้อย 2 ตัวอักษร'
  }

  if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email)) {
    errors.email = 'รูปแบบอีเมลไม่ถูกต้อง'
  }

  if (!sessions.includes(session as (typeof sessions)[number])) {
    errors.session = 'กรุณาเลือกรอบกิจกรรม'
  }

  if (!acceptedTerms) {
    errors.terms = 'ต้องยอมรับเงื่อนไขก่อนลงทะเบียน'
  }

  const values = { name, email, session }

  if (Object.keys(errors).length > 0) {
    return {
      status: 'error',
      message: 'กรุณาตรวจสอบข้อมูลที่ไฮไลต์',
      errors,
      values,
    }
  }

  await new Promise((resolve) => setTimeout(resolve, 800))

  return {
    status: 'success',
    message: 'ลงทะเบียนสำเร็จ',
    registrationCode: crypto.randomUUID().slice(0, 8).toUpperCase(),
    errors: {},
    values,
  }
}
```

ข้อสังเกต:

- HTML validation ช่วยผู้ใช้ แต่ห้ามใช้แทน Server validation
- ทุกค่าจาก `FormData` อาจเป็น string, File หรือ null
- อย่าส่งข้อมูลส่วนตัวไป `console.log` ใน Production
- การหน่วงเวลาใช้เพื่อให้เห็น Pending state เท่านั้น

## 3. Client Form

สร้าง `src/app/register/registration-form.tsx`

```tsx
'use client'

import { useActionState } from 'react'
import {
  initialState,
  registerForEvent,
} from './actions'

export function RegistrationForm() {
  const [state, formAction, isPending] = useActionState(
    registerForEvent,
    initialState,
  )

  if (state.status === 'success') {
    return (
      <section
        aria-labelledby="success-title"
        className="rounded-2xl border border-emerald-200 bg-emerald-50 p-8"
      >
        <h2 id="success-title" className="text-2xl font-bold text-emerald-900">
          ลงทะเบียนสำเร็จ
        </h2>
        <p className="mt-3">ผู้ลงทะเบียน: {state.values.name}</p>
        <p>รอบ: {state.values.session}</p>
        <p className="mt-4 font-mono text-xl">
          Code: {state.registrationCode}
        </p>
      </section>
    )
  }

  return (
    <form action={formAction} noValidate className="space-y-5">
      <div>
        <label htmlFor="name" className="block font-medium">
          ชื่อ–นามสกุล
        </label>
        <input
          id="name"
          name="name"
          defaultValue={state.values.name}
          aria-invalid={Boolean(state.errors.name)}
          aria-describedby={state.errors.name ? 'name-error' : undefined}
          className="mt-1 w-full rounded-lg border px-3 py-2 aria-invalid:border-red-600"
        />
        {state.errors.name && (
          <p id="name-error" className="mt-1 text-sm text-red-700">
            {state.errors.name}
          </p>
        )}
      </div>

      <div>
        <label htmlFor="email" className="block font-medium">อีเมล</label>
        <input
          id="email"
          name="email"
          type="email"
          inputMode="email"
          defaultValue={state.values.email}
          aria-invalid={Boolean(state.errors.email)}
          aria-describedby={state.errors.email ? 'email-error' : undefined}
          className="mt-1 w-full rounded-lg border px-3 py-2 aria-invalid:border-red-600"
        />
        {state.errors.email && (
          <p id="email-error" className="mt-1 text-sm text-red-700">
            {state.errors.email}
          </p>
        )}
      </div>

      <div>
        <label htmlFor="session" className="block font-medium">รอบกิจกรรม</label>
        <select
          id="session"
          name="session"
          defaultValue={state.values.session}
          aria-invalid={Boolean(state.errors.session)}
          className="mt-1 w-full rounded-lg border px-3 py-2"
        >
          <option value="">เลือกรอบ</option>
          <option value="morning">09:00–12:00</option>
          <option value="afternoon">13:00–16:00</option>
        </select>
        {state.errors.session && (
          <p className="mt-1 text-sm text-red-700">{state.errors.session}</p>
        )}
      </div>

      <div>
        <label className="flex items-start gap-3">
          <input type="checkbox" name="terms" className="mt-1" />
          <span>ยอมรับเงื่อนไขและอนุญาตให้ใช้ข้อมูลเพื่อลงทะเบียนกิจกรรม</span>
        </label>
        {state.errors.terms && (
          <p className="mt-1 text-sm text-red-700">{state.errors.terms}</p>
        )}
      </div>

      {state.message && (
        <p
          role={state.status === 'error' ? 'alert' : 'status'}
          className="rounded-lg bg-red-50 p-3 text-red-800"
        >
          {state.message}
        </p>
      )}

      <button
        type="submit"
        disabled={isPending}
        className="rounded-lg bg-indigo-700 px-5 py-3 font-medium text-white disabled:cursor-wait disabled:opacity-60"
      >
        {isPending ? 'กำลังลงทะเบียน…' : 'ลงทะเบียน'}
      </button>
    </form>
  )
}
```

`useActionState` คืนสามค่า:

1. ผลลัพธ์ล่าสุดจาก Action
2. Action ที่ส่งให้ `<form>`
3. Pending flag ระหว่าง Action ทำงาน

## Server Action หรือ Route Handler

| งาน | ตัวเลือก |
| --- | --- |
| Form หรือ mutation จาก UI ของ Next.js | Server Action |
| Public REST API | Route Handler |
| Webhook จากระบบภายนอก | Route Handler |
| อ่านข้อมูลเพื่อ render Server Component | เรียก data source โดยตรง |

## Lab และ Challenge

1. เพิ่มช่องเบอร์โทรศัพท์แบบไม่บังคับ
2. เพิ่มเงื่อนไขห้ามใช้อีเมลซ้ำ โดยจำลองด้วย array
3. ทำ Error summary ที่ลิงก์ไปแต่ละ field
4. ทดสอบส่งด้วย Keyboard และ Screen reader

Challenge: หลังสำเร็จบันทึกข้อมูลในฐานข้อมูลของสัปดาห์ 7 และ redirect ไปหน้ารายละเอียด โดยเรียก `redirect()` นอก `try/catch`

## Definition of Done

- [ ] Action อยู่ในไฟล์ที่มี `'use server'`
- [ ] Validate ทุก field ที่ Server
- [ ] แสดงข้อผิดพลาดใกล้ field และเชื่อมด้วย ARIA
- [ ] ปุ่มถูก disable และมีข้อความระหว่าง Pending
- [ ] Success state แสดงข้อมูลสำคัญ
- [ ] ไม่มี Secret หรือข้อมูลส่วนตัวใน Client log

## Exit ticket

1. เพราะเหตุใดยังต้อง validate ที่ Server แม้ input มี `required`
2. Server Action ต่างจาก Route Handler อย่างไร
3. `useActionState` ช่วยลด state ใดที่เราต้องเขียนเอง
