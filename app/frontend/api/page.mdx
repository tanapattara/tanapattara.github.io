# API

API ย่อมาจาก Application Programming Interface คือ ช่องทางการสื่อสารที่ช่วยให้ระบบซอฟต์แวร์หรือแอปพลิเคชันต่างๆ สามารถแลกเปลี่ยนข้อมูลและทำงานร่วมกันได้อย่างมีประสิทธิภาพ เปรียบเสมือน "คนกลาง" หรือ "สะพานเชื่อม" ที่ช่วยให้ระบบต่างๆ สื่อสารกันได้โดยไม่ต้องเข้าใจรายละเอียดภายในของกันและกัน

**API ทำงานอย่างไร?**

1. **คำขอ (Request):** แอปพลิเคชันหนึ่งส่งคำขอไปยัง API เพื่อขอข้อมูลหรือบริการบางอย่าง
2. **ประมวลผล (Process):** API รับคำขอ ประมวลผล และดึงข้อมูลที่ต้องการจากระบบอื่นหรือฐานข้อมูล
3. **ตอบกลับ (Response):** API ส่งข้อมูลที่ประมวลผลแล้วกลับไปยังแอปพลิเคชันที่ส่งคำขอมา

## Request

Request API หรือ HTTP request methods มีหลายแบบ แต่ที่นิยมใช้กันมากมี 4 แบบหลักๆ ดังนี้:

- **GET:** ใช้สำหรับขอข้อมูลจากเซิร์ฟเวอร์ โดยไม่เปลี่ยนแปลงข้อมูลใดๆ บนเซิร์ฟเวอร์
- **POST:** ใช้สำหรับส่งข้อมูลไปยังเซิร์ฟเวอร์ เพื่อสร้างทรัพยากรใหม่ หรืออัปเดตข้อมูลที่มีอยู่
- **PUT:** ใช้สำหรับอัปเดตทรัพยากรที่มีอยู่บนเซิร์ฟเวอร์ โดยแทนที่ข้อมูลเดิมทั้งหมดด้วยข้อมูลใหม่
- **DELETE:** ใช้สำหรับลบทรัพยากรบนเซิร์ฟเวอร์

นอกจากนี้ยังมี HTTP request methods อื่นๆ ที่ใช้น้อยกว่า เช่น:

- **HEAD:** คล้ายกับ GET แต่จะส่งกลับเฉพาะส่วนหัว (header) ของข้อมูล ไม่ส่งกลับเนื้อหา (body)
- **OPTIONS:** ใช้สำหรับขอข้อมูลเกี่ยวกับตัวเลือกการสื่อสารที่เซิร์ฟเวอร์รองรับ
- **PATCH:** ใช้สำหรับอัปเดตทรัพยากรบางส่วนบนเซิร์ฟเวอร์ โดยไม่จำเป็นต้องส่งข้อมูลทั้งหมด
- **CONNECT:** ใช้สำหรับสร้างช่องทางการสื่อสารแบบ tunnel ระหว่างไคลเอนต์กับเซิร์ฟเวอร์

ในการใช้งาน API แต่ละครั้ง เราจะต้องระบุ HTTP request method ที่เหมาะสมกับวัตถุประสงค์ของเรา เพื่อให้เซิร์ฟเวอร์สามารถประมวลผลคำขอของเราได้อย่างถูกต้อง

สมมติว่าเรามี API สำหรับจัดการข้อมูลหนังสือในร้านหนังสือออนไลน์ ดัวยคำสั่งพื้นฐาน CRUD หรือก็คือ Create Read Update Delete เราจะได้คำสั่งพื้นฐานในการเรียกใช้งาน ผ่าน URL ดังนี้

| Method | Endpoint | Sample |
| --- | --- | --- |
| GET | **/books** | **https://url/api/v1/book** |
| GET | /book/&#123;id&#125; | **https://url/api/v1/book/1** |
| POST | /books | **https://url/api/v1/book** |
| PUT | /book/&#123;id&#125; | **https://url/api/v1/book/1** |
| DELETE | /book/&#123;id&#125; | **https://url/api/v1/book/1** |

**1. GET /book**

- **คำอธิบาย:** ใช้สำหรับดึงรายชื่อหนังสือทั้งหมดที่มีอยู่ในร้าน ส่วนใหญ่แล้วการดังข้อมูลในลักษณะนี้จะเป็นการดึงข้อมูลทั้งหมด บางครั้งไม่จำเป็นต้องส่ง Request body
- **ตัวอย่าง Response:**

```json
[
    {
        "id": 1,
        "title": "Harry Potter and the Philosopher's Stone",
        "author": "J.K. Rowling",
        "price": 19.99
    },
    {
        "id": 2,
        "title": "The Lord of the Rings",
        "author": "J.R.R. Tolkien",
        "price": 29.99
    }
]
```

**2. GET /book/&#123;id&#125;**

- **คำอธิบาย:** ใช้สำหรับดึงรายชื่อหนังสือ โดยระบุไอดี
- **ตัวอย่าง Response:**

```json
{
    "id": 3,
    "title": "To Kill a Mockingbird",
    "author": "Harper Lee",
    "price": 14.99
}
```

**3. POST /book**

- **คำอธิบาย:** ใช้สำหรับเพิ่มหนังสือใหม่เข้าสู่ร้าน
- **ตัวอย่าง Request Body:**

```json
{
    "title": "To Kill a Mockingbird",
    "author": "Harper Lee",
    "price": 14.99
}
```

- **ตัวอย่าง Response:** (อาจจะส่งกลับข้อมูลหนังสือที่เพิ่มเข้าไปใหม่ พร้อม ID)

```json
{
    "id": 3,
    "title": "To Kill a Mockingbird",
    "author": "Harper Lee",
    "price": 14.99
}
```

**4. PUT /book/&#123;id&#125;** (สมมติว่า &#123;id&#125; คือ 1)

- 
- **คำอธิบาย:** ใช้สำหรับแก้ไขข้อมูลหนังสือที่มีอยู่แล้ว (ในที่นี้คือหนังสือที่มี ID เป็น 1)
- **ตัวอย่าง Request Body:**

```json
{
    "title": "Harry Potter and the Sorcerer's Stone",
    "price": 21.99
}

```

- **ตัวอย่าง Response:** (อาจจะส่งกลับข้อมูลหนังสือที่แก้ไขแล้ว)

```json
{
    "id": 1,
    "title": "Harry Potter and the Sorcerer's Stone",
    "author": "J.K. Rowling",
    "price": 21.99
}
```

**5. DELETE /book/&#123;id&#125;** (สมมติว่า &#123;id&#125; คือ 2)

- **คำอธิบาย:** ใช้สำหรับลบหนังสือออกจากร้าน (ในที่นี้คือหนังสือที่มี ID เป็น 2)
- **ตัวอย่าง Response:** (อาจจะส่งกลับข้อความยืนยันการลบ หรือ status code 204 No Content)

## Response

เป็นผลลัพท์ที่เราได้จาก API เราจะได้กลับมาในรูปแบบของตัวอักษร โดยมีรูปแบบเป็น XML หรือ JSON ตามแต่ง API ระบุ โดยปัจจุบันนิยมใช้ JSON มากที่สุด เนื่องจากสะดวก นานไม่ใหญ่ ส่งข้อมูลได้รวดเร็ว

JSON (JavaScript Object Notation) คือ รูปแบบการแลกเปลี่ยนข้อมูล (data interchange format) ที่มีลักษณะเป็นข้อความ (text-based) และสามารถอ่านได้ง่ายทั้งโดยมนุษย์และเครื่องคอมพิวเตอร์ JSON ถูกนำมาใช้กันอย่างแพร่หลายในการส่งข้อมูลระหว่างเว็บเซิร์ฟเวอร์และเว็บแอปพลิเคชัน หรือระหว่างแอปพลิเคชันต่างๆ

**ลักษณะสำคัญของ JSON:**

- **โครงสร้าง:** JSON มีโครงสร้างที่เรียบง่าย โดยใช้คู่ของ "key-value" (ชื่อ-ค่า) ในการจัดเก็บข้อมูล ค่า (value) สามารถเป็นได้ทั้งตัวเลข, ข้อความ, บูลีน (true/false), อาร์เรย์, วัตถุ, หรือค่า null
- **ไวยากรณ์:** JSON มีไวยากรณ์ (syntax) ที่ใกล้เคียงกับ JavaScript ทำให้สามารถใช้งานร่วมกับ JavaScript ได้ง่าย
- **ความยืดหยุ่น:** JSON สามารถใช้กับภาษาโปรแกรมต่างๆ ได้หลากหลาย ไม่จำกัดเฉพาะ JavaScript เท่านั้น

**ตัวอย่าง JSON:**

```json
{
  "name": "John Doe",
  "age": 30,
  "city": "New York",
  "isMarried": false,
  "hobbies": ["reading", "traveling", "coding"]
}
```

ในตัวอย่างนี้:

- `"name"`, `"age"`, `"city"`, `"isMarried"`, `"hobbies"` เป็น key
- `"John Doe"`, `30`, `"New York"`, `false`, `["reading", "traveling", "coding"]` เป็น value

**JSON กับ API:**

JSON มักถูกใช้เป็นรูปแบบข้อมูลในการสื่อสารผ่าน API (Application Programming Interface) เนื่องจากความเรียบง่ายและความสามารถในการทำงานร่วมกับภาษาต่างๆ ได้ดี เมื่อแอปพลิเคชันหนึ่งร้องขอข้อมูลจาก API อีกตัวหนึ่ง ข้อมูลที่ส่งกลับมักจะอยู่ในรูปแบบ JSON ซึ่งแอปพลิเคชันที่ได้รับสามารถนำไปประมวลผลและแสดงผลได้ง่าย
