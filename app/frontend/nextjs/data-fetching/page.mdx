# การดึงข้อมูลใน Next.js

App Router เปิดให้ Server Component ใช้ `async`/`await` ได้โดยตรง การอ่านข้อมูลภายในแอปจึงควรเริ่มที่ Server Component ส่วน Client-side fetching เหมาะกับข้อมูลที่ต้องเปลี่ยนตาม interaction หลังหน้าแสดงแล้ว เช่น autocomplete หรือ dashboard ที่ refresh เป็นระยะ

## เลือกรูปแบบการดึงข้อมูล

| สถานการณ์ | แนวทาง |
| --- | --- |
| อ่านข้อมูลเพื่อสร้างหน้า | ดึงใน Server Component |
| อ่านฐานข้อมูลของระบบเดียวกัน | เรียก database/query function โดยตรง |
| ส่งข้อมูลให้ Browser ใช้ต่อ | ดึงบน Server แล้วส่ง props |
| Client ต้อง refresh ข้อมูลเอง | เรียก Route Handler จาก Client |
| เพิ่ม แก้ไข หรือลบจาก UI | ใช้ Server Action |

## ดึง External API ใน Server Component

```tsx
type Book = {
  id: number
  title: string
  price: number
}

async function getBooks(): Promise<Book[]> {
  const response = await fetch('https://api.example.com/books')

  if (!response.ok) {
    throw new Error('ไม่สามารถโหลดข้อมูลหนังสือได้')
  }

  return response.json()
}

export default async function BooksPage() {
  const books = await getBooks()

  return (
    <ul>
      {books.map((book) => (
        <li key={book.id}>
          {book.title} — {book.price} บาท
        </li>
      ))}
    </ul>
  )
}
```

ตรวจ `response.ok` ทุกครั้ง เพราะ `fetch` จะไม่ throw อัตโนมัติเมื่อได้รับ status เช่น 404 หรือ 500

## เรียก Data Layer โดยตรง

```tsx
// app/books/page.tsx
import { listBooks } from '@/lib/books'

export default async function BooksPage() {
  const books = await listBooks()
  return <BookList books={books} />
}
```

Server Component เรียก `listBooks()` ได้โดยไม่ต้องผ่าน `/api/books` ช่วยลด network round trip และรวมกฎการเข้าถึงข้อมูลไว้ใน Server เมื่อเปลี่ยนจาก Repository ตัวอย่างเป็นฐานข้อมูลจริง ให้แก้ implementation ใน Data Layer โดยไม่ต้องเปลี่ยน Component

## หลีกเลี่ยง Data Waterfall

โค้ดต่อไปนี้รอทีละ request แม้ข้อมูลไม่ขึ้นต่อกัน

```tsx
const books = await getBooks()
const categories = await getCategories()
const promotions = await getPromotions()
```

เริ่มพร้อมกันด้วย `Promise.all`

```tsx
const [books, categories, promotions] = await Promise.all([
  getBooks(),
  getCategories(),
  getPromotions(),
])
```

หากข้อมูลชุดที่สองต้องใช้ ID จากชุดแรก การรอแบบลำดับจึงสมเหตุสมผล ควรดู dependency ของข้อมูลก่อนเปลี่ยนเป็น parallel

## Streaming ด้วย Suspense

แสดงส่วนที่พร้อมก่อน โดยไม่ต้องรอทั้งหน้า

```tsx
import { Suspense } from 'react'

export default function DashboardPage() {
  return (
    <main>
      <h1>ภาพรวมร้านหนังสือ</h1>
      <Suspense fallback={<p>กำลังโหลดหนังสือ...</p>}>
        <BookList />
      </Suspense>
      <Suspense fallback={<p>กำลังโหลดโปรโมชั่น...</p>}>
        <PromotionList />
      </Suspense>
    </main>
  )
}

async function BookList() {
  const books = await getBooks()
  return <ul>{books.map((book) => <li key={book.id}>{book.title}</li>)}</ul>
}
```

อีกทางหนึ่งคือสร้าง `loading.tsx` ข้าง `page.tsx` เพื่อกำหนด fallback ให้ route segment ทั้งส่วน

## Client-side Fetching เมื่อจำเป็น

```tsx
'use client'

import { useEffect, useState } from 'react'

type Suggestion = { id: string; title: string }

export function Suggestions({ query }: { query: string }) {
  const [items, setItems] = useState<Suggestion[]>([])

  useEffect(() => {
    if (!query) return

    const controller = new AbortController()

    async function loadSuggestions() {
      try {
        const response = await fetch(
          `/api/books/search?q=${encodeURIComponent(query)}`,
          { signal: controller.signal },
        )

        if (!response.ok) {
          throw new Error(`โหลดคำแนะนำไม่สำเร็จ (${response.status})`)
        }

        const body = (await response.json()) as { data: Suggestion[] }
        setItems(body.data)
      } catch (error) {
        if (error instanceof DOMException && error.name === 'AbortError') return
        console.error(error)
      }
    }

    void loadSuggestions()

    return () => controller.abort()
  }, [query])

  return <ul>{items.map((item) => <li key={item.id}>{item.title}</li>)}</ul>
}
```

การยกเลิก request เก่าช่วยป้องกันผลค้นหาเก่ากลับมาทับผลล่าสุด ในโปรเจกต์จริงอาจใช้ library ที่จัดการ cache, retry และ deduplication ให้

## Static Export

Static Export ดึงข้อมูลได้ตอน Build แต่ไม่มี Server ให้ดึงฐานข้อมูลตาม request หลัง deploy หากข้อมูลเปลี่ยนต้อง Build ใหม่ หรือให้ Client เรียก API ภายนอกที่มีอยู่จริง

## แบบฝึกหัด

สร้างหน้า Dashboard ที่ดึงหนังสือ หมวดหมู่ และโปรโมชั่นแบบ parallel จากนั้นแยกโปรโมชั่นไว้ใน `Suspense` และทดลองทำให้ API ช้าลงเพื่อสังเกตลำดับการแสดงผล
