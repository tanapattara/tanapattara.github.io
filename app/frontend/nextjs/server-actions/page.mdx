# Form และ Server Actions

Server Function คือ async function ที่ทำงานบน Server เมื่อใช้กับการส่ง Form หรือ mutation จะเรียกว่า Server Action ช่วยให้ UI เรียกโค้ด Server ได้โดยไม่ต้องสร้าง endpoint สำหรับทุกปุ่ม และทำงานร่วมกับ cache กับ React transition

## สร้าง Server Action

แยก action ไว้ในไฟล์ที่ขึ้นต้นด้วย `'use server'`

```tsx
// app/books/actions.ts
'use server'

import { revalidatePath } from 'next/cache'
import { redirect } from 'next/navigation'
import { insertBook } from '@/lib/books'
import { requireAdmin } from '@/lib/dal'

export type FormState = {
  error?: string
}

export async function createBook(
  _previousState: FormState,
  formData: FormData,
): Promise<FormState> {
  const title = formData.get('title')
  const priceText = formData.get('price')

  const admin = await requireAdmin()
  if (!admin) return { error: 'คุณไม่มีสิทธิ์เพิ่มหนังสือ' }

  if (typeof title !== 'string' || title.trim().length < 2) {
    return { error: 'ชื่อหนังสือต้องมีอย่างน้อย 2 ตัวอักษร' }
  }

  if (typeof priceText !== 'string' || priceText.trim() === '') {
    return { error: 'กรุณาระบุราคา' }
  }

  const price = Number(priceText)
  if (!Number.isFinite(price) || price < 0) {
    return { error: 'กรุณาระบุราคาที่ถูกต้อง' }
  }

  let book
  try {
    book = await insertBook({
      title: title.trim(),
      price,
    })
  } catch {
    return { error: 'บันทึกข้อมูลไม่สำเร็จ กรุณาลองใหม่' }
  }

  revalidatePath('/books')
  redirect(`/books/${book.id}`)
}
```

เรียก `redirect()` นอก `try...catch` เพราะฟังก์ชันนี้ส่งสัญญาณควบคุมภายในด้วยการ throw หากจับไว้ Navigation จะไม่เกิดขึ้น

## Form ที่แสดง Pending และ Error

```tsx
// app/books/new/book-form.tsx
'use client'

import { useActionState } from 'react'
import { createBook, type FormState } from '../actions'

const initialState: FormState = {}

export function BookForm() {
  const [state, formAction, pending] = useActionState(createBook, initialState)

  return (
    <form action={formAction}>
      <div>
        <label htmlFor="title">ชื่อหนังสือ</label>
        <input id="title" name="title" required minLength={2} />
      </div>

      <div>
        <label htmlFor="price">ราคา</label>
        <input id="price" name="price" type="number" min="0" step="0.01" required />
      </div>

      {state.error && <p role="alert">{state.error}</p>}

      <button type="submit" disabled={pending}>
        {pending ? 'กำลังบันทึก...' : 'เพิ่มหนังสือ'}
      </button>
    </form>
  )
}
```

Browser ตรวจ `required` และ `minLength` เพื่อ UX ที่ดี แต่ Server Action ต้องตรวจซ้ำเสมอ เพราะผู้ใช้สามารถข้าม validation ฝั่ง Browser ได้

## Action แบบรับ Argument

การลบต้องรู้ `id` สามารถใช้ `bind` โดยไม่ต้องสร้าง hidden input

```tsx
// app/books/actions.ts
'use server'

import { revalidatePath } from 'next/cache'
import { removeBook } from '@/lib/books'
import { requireAdmin } from '@/lib/dal'

export async function deleteBook(id: string) {
  const admin = await requireAdmin()
  if (!admin) return

  const deleted = await removeBook(id)
  if (!deleted) return

  revalidatePath('/books')
}
```

```tsx
import { deleteBook } from './actions'

export function DeleteBookButton({ id }: { id: string }) {
  const deleteBookWithId = deleteBook.bind(null, id)

  return (
    <form action={deleteBookWithId}>
      <button type="submit">ลบ</button>
    </form>
  )
}
```

Server Action เป็น public entry point ของระบบ ผู้ใช้สามารถเรียก action โดยไม่ผ่านปุ่มที่เราสร้าง จึงต้องตรวจ session และสิทธิ์ **ภายใน action** ก่อนแก้ข้อมูลทุกครั้ง

ตัวอย่างใช้ `requireAdmin()` จากบท Authentication และ Authorization หากยังไม่ได้สร้างฟังก์ชันนี้ ให้หยุดไว้ที่การแสดง Form และอย่าเปิด mutation ให้ผู้ใช้อื่นเรียกจนกว่าจะเพิ่มการตรวจสิทธิ์

## Progressive Enhancement

Form ที่ผูก Server Action สามารถ submit ได้แม้ JavaScript ยังโหลดไม่เสร็จ เมื่อ JavaScript พร้อม React จะจัดการ pending state และอัปเดต UI โดยไม่ reload ทั้งหน้า

## Server Action ไม่ควรใช้ทำอะไร

- ไม่ใช้แทน GET endpoint สาธารณะ เพราะ Action เรียกผ่าน POST
- ไม่ใช้รับ webhook หรือ request จาก mobile app
- ไม่คืน class instance, stream หรือข้อมูลที่ serialize ไม่ได้
- ไม่เชื่อถือ ID, role หรือราคาที่มาจาก Client โดยไม่ตรวจฐานข้อมูล

## Static Export

Server Actions ต้องมี Server runtime จึงใช้ไม่ได้เมื่อ deploy ด้วย `output: "export"` ให้สร้างโปรเจกต์ทดลองแบบ Node.js/Vercel หรือใช้ API ภายนอกกับ Client form แทน

## แบบฝึกหัด

สร้าง Form เพิ่มและลบหนังสือ เพิ่ม validation ทั้ง Client และ Server แสดง Pending state และ Error จากนั้นทดสอบส่งค่าติดลบหรือชื่อว่างโดยปิด validation ใน Browser DevTools
