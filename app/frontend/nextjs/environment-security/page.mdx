# Environment Variables และ Security

Environment Variable แยกค่าตั้งออกจาก source code เช่น URL ฐานข้อมูลและ API key แต่การย้าย secret ไป `.env.local` ไม่ได้ทำให้ระบบปลอดภัยอัตโนมัติ ต้องควบคุมด้วยว่าไฟล์หรือ component ใดสามารถอ่านค่าและข้อมูลใดถูกส่งไป Browser

## ไฟล์ Environment

```dotenv
# .env.local — ห้าม commit
DATABASE_URL="postgresql://user:password@localhost:5432/bookstore"
PAYMENT_API_SECRET="replace-with-a-real-secret"

# ค่านี้ตั้งใจเปิดเผยให้ Browser
NEXT_PUBLIC_SITE_URL="http://localhost:3000"
```

ค่าที่ขึ้นต้น `NEXT_PUBLIC_` จะถูกฝังใน Client bundle ตอน Build ผู้ใช้ทุกคนอ่านได้ จึงใช้เฉพาะค่าที่เปิดเผยได้ เช่น public site URL หรือ public analytics ID

## อ่าน Secret เฉพาะ Server

```tsx
// lib/payment.ts
import 'server-only'

export async function createPayment(amount: number) {
  const secret = process.env.PAYMENT_API_SECRET
  if (!secret) throw new Error('PAYMENT_API_SECRET is not configured')

  return fetch('https://payments.example.com/charges', {
    method: 'POST',
    headers: { Authorization: `Bearer ${secret}` },
    body: JSON.stringify({ amount }),
  })
}
```

`server-only` ทำให้เกิด Build Error หากมี Client Component import module นี้ อย่าส่ง `secret` กลับเป็น prop หรือ JSON response

## Validate Environment ตอนเริ่มระบบ

```tsx
// lib/env.ts
import 'server-only'

function required(name: string): string {
  const value = process.env[name]
  if (!value) throw new Error(`Missing environment variable: ${name}`)
  return value
}

export const env = {
  databaseUrl: required('DATABASE_URL'),
  paymentSecret: required('PAYMENT_API_SECRET'),
}
```

การ fail ตั้งแต่เริ่ม Build/Server เข้าใจง่ายกว่าปล่อยให้ระบบล้มเมื่อผู้ใช้ทำรายการจริง

## Validation และ Output Encoding

ข้อมูลจาก `formData`, JSON body, URL params, query string, cookies และ headers เป็น input ที่ไม่ควรเชื่อถือทั้งหมด

```tsx
function parsePrice(value: unknown) {
  const price = Number(value)
  if (!Number.isFinite(price) || price < 0 || price > 1_000_000) {
    throw new Error('Invalid price')
  }
  return price
}
```

React escape ข้อความที่ render ใน JSX โดยปกติ แต่ `dangerouslySetInnerHTML` สามารถเปิดช่อง XSS ได้ จึงไม่ควรใช้กับ HTML จากผู้ใช้หากยังไม่ได้ sanitize

## Cookie ที่ปลอดภัย

```tsx
import { cookies } from 'next/headers'

export async function saveSession(token: string) {
  const cookieStore = await cookies()

  cookieStore.set('session', token, {
    httpOnly: true,
    secure: process.env.NODE_ENV === 'production',
    sameSite: 'lax',
    path: '/',
    maxAge: 60 * 60 * 24 * 7,
  })
}
```

- `httpOnly` ป้องกัน JavaScript ใน Browser อ่าน session
- `secure` ส่ง cookie ผ่าน HTTPS เท่านั้นใน production
- `sameSite` ลดความเสี่ยง CSRF บางรูปแบบ
- `maxAge` จำกัดอายุ session

อย่าเก็บ password หรือข้อมูลสำคัญที่ไม่ได้เข้ารหัสไว้ใน cookie

## ตรวจสิทธิ์ใกล้ Data Source

การซ่อนปุ่ม Admin เป็นเพียง UX ไม่ใช่ Security ผู้โจมตีเรียก Server Action หรือ Route Handler โดยตรงได้

```tsx
import { removeBook } from '@/lib/books'

export async function deleteBook(id: string) {
  'use server'

  const session = await verifySession()
  if (!session || session.user.role !== 'admin') {
    throw new Error('Forbidden')
  }

  const deleted = await removeBook(id)
  if (!deleted) throw new Error('Book not found')
}
```

ตรวจ authorization ทุก entry point ที่แก้หรืออ่านข้อมูลสำคัญ และเลือกคืนข้อมูลเฉพาะ field ที่ผู้ใช้จำเป็นต้องเห็น

## Security Checklist

- ไม่ commit `.env.local`, token หรือข้อมูลนักศึกษา
- Hash password ด้วย algorithm สำหรับ password โดยเฉพาะ
- ใช้ prepared query หรือ ORM แทนต่อ SQL string
- Validate file type และขนาด upload
- Rate limit login, register และ public API
- ตรวจ dependency และอัปเดต security patch
- Log เหตุการณ์สำคัญโดยไม่บันทึก password/token
- ใช้ HTTPS ใน production

## Static Export

Environment ที่ใช้ตอน Build อาจถูกฝังลง HTML หรือ JavaScript ระวังเป็นพิเศษกับ Static Export ซึ่งไม่มี Server ช่วยเก็บ secret หลัง deploy หาก Browser ต้องเรียกบริการภายนอก ให้ใช้ API ที่ออกแบบสำหรับ public client หรือมี backend แยก

## แบบฝึกหัด

ตรวจโครงการตัวอย่างว่า environment ตัวใดเปิดเผยได้ ย้าย database module ไปไฟล์ที่ import `server-only` เพิ่ม validation สำหรับราคา และเขียน test case สำหรับ input ติดลบ, string, ค่าว่าง และค่าที่ใหญ่ผิดปกติ
