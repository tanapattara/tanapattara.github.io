# สัปดาห์ 13: Testing และ Debugging

เป้าหมายของการทดสอบคือให้ทีมเปลี่ยนโค้ดได้อย่างมั่นใจ เลือกระดับ test ตามความเสี่ยงและ feedback speed พร้อมใช้ TypeScript, lint, Expo Doctor และเครื่องมือ debug เป็น quality gates

## ผลลัพธ์การเรียนรู้

- แยก Type checking, linting, unit, component, integration และ E2E tests
- ทดสอบ pure function, reducer, custom hook และ Component interaction
- mock network/storage/device boundary แทนการ mock implementation ทุกชั้น
- ใช้ Expo Doctor และ debugger หา root cause
- สร้าง EAS Preview Build สำหรับการทดสอบร่วมกัน

## Testing pyramid สำหรับ Campus Events

| ระดับ | ตัวอย่าง | จุดเด่น |
| --- | --- | --- |
| Static | TypeScript, ESLint, Expo Doctor | เร็ว จับ configuration และชนิดข้อมูล |
| Unit | validation, reducer, formatter | เร็วและระบุสาเหตุง่าย |
| Component | EventCard, Login form | ตรวจ UI กับ interaction |
| Integration | Login + session + protected route | ตรวจหลาย boundary ร่วมกัน |
| E2E | Login → Favorite → Register | ใกล้ประสบการณ์จริง แต่ช้า/ดูแลยากกว่า |

## Quality commands

ติดตั้ง Jest preset สำหรับ Expo และ React Native Testing Library โดยใช้เวอร์ชันที่เข้ากับ baseline ของโปรเจกต์:

```bash
npx expo install jest jest-expo @types/jest @testing-library/react-native --dev
```

เพิ่ม script และ preset ใน `package.json`:

```json
{
  "scripts": {
    "test": "jest",
    "typecheck": "tsc --noEmit",
    "lint": "expo lint"
  },
  "jest": {
    "preset": "jest-expo"
  }
}
```

ใช้ scripts ที่มีอยู่ในโปรเจกต์จริง อย่าคัดลอกชื่อคำสั่งโดยไม่ตรวจ `package.json`

```bash
npx tsc --noEmit
npx expo lint
npx expo-doctor
npm test
```

## Unit test: reducer

```tsx
import { favoriteReducer } from '../favorites-reducer';

describe('favoriteReducer', () => {
  it('adds and removes the same event id', () => {
    const added = favoriteReducer([], { type: 'toggle', id: 'event-1' });
    expect(added).toEqual(['event-1']);

    const removed = favoriteReducer(added, { type: 'toggle', id: 'event-1' });
    expect(removed).toEqual([]);
  });
});
```

## Component test: EventCard

ทดสอบสิ่งที่ผู้ใช้มองเห็นและกระทำ ไม่ผูก test กับชื่อ state หรือโครงสร้างภายใน

```tsx
import { fireEvent, render, screen } from '@testing-library/react-native';
import { EventCard } from '../EventCard';
import type { CampusEvent } from '../types';

const event: CampusEvent = {
  id: 'event-1',
  title: 'Mobile Dev Meetup',
  description: 'แลกเปลี่ยนประสบการณ์พัฒนา Mobile App',
  startsAt: '2026-09-10T09:00:00+07:00',
  imageUrl: 'https://example.com/event.jpg',
  location: {
    name: 'อาคารวิทยวิภาส',
    latitude: 13.7563,
    longitude: 100.5018,
  },
};

it('opens the selected event', () => {
  const onOpen = jest.fn();
  const onToggleFavorite = jest.fn();

  render(
    <EventCard
      event={event}
      isFavorite={false}
      onOpen={onOpen}
      onToggleFavorite={onToggleFavorite}
    />
  );

  fireEvent.press(screen.getByText(event.title));
  expect(onOpen).toHaveBeenCalledWith(event.id);
});
```

## Integration-style test: Registration form

ทดสอบหลาย Component ร่วมกับ validation และ submission boundary โดย mock เฉพาะ API function:

```tsx
import { fireEvent, render, screen, waitFor } from '@testing-library/react-native';
import { RegistrationForm } from '../RegistrationForm';

it('submits valid registration data', async () => {
  const registerForEvent = jest
    .fn()
    .mockResolvedValue({ registrationId: 'reg-1' });

  render(
    <RegistrationForm eventId="event-1" onSubmit={registerForEvent} />
  );

  fireEvent.changeText(screen.getByLabelText('ชื่อ-นามสกุล'), 'สมชาย ใจดี');
  fireEvent.changeText(screen.getByLabelText('อีเมล'), 'somchai@example.com');
  fireEvent.press(screen.getByRole('button', { name: 'ลงทะเบียน' }));

  await waitFor(() => {
    expect(registerForEvent).toHaveBeenCalledWith({
      eventId: 'event-1',
      fullName: 'สมชาย ใจดี',
      email: 'somchai@example.com',
    });
  });
});
```

## Integration และ E2E scope

- Validation: invalid email แสดง error และไม่เรียก API
- Login flow: token สำเร็จ → เก็บ SecureStore → เปิด protected route
- Offline: API ล้มเหลว → แสดง cache พร้อม banner
- Notification: event ID → เปิด Detail หรือ Not found
- E2E smoke: Login → Favorite → Register → Logout

### E2E introduction: Maestro

ใช้ Maestro เป็นบทนำสำหรับ smoke test บน Preview Build เพราะอ่าน flow ได้ง่ายและไม่ต้องเขียน test framework ขนาดใหญ่ใน Lab นี้

```yaml
appId: th.ac.example.campusevents
---
- launchApp
- tapOn: "เข้าสู่ระบบ"
- inputText: "student@example.com"
- tapOn: "ดำเนินการต่อ"
- assertVisible: "กิจกรรม"
```

E2E เป็นงานต่อยอด ไม่บังคับให้ทุกทีมติดตั้ง environment เต็มรูปแบบภายใน 2 ชั่วโมง แต่ต้องอธิบาย smoke flow และทดสอบ Preview Build ด้วยตนเอง

<Callout type="warning">
  อย่าใช้ production account หรือข้อมูลจริงในการทดสอบ และอย่า hard-code secret ใน test fixture ใช้ test environment ที่ล้างข้อมูลได้
</Callout>

## Debugging workflow

1. ทำให้ปัญหาเกิดซ้ำด้วยขั้นตอนสั้นที่สุด
2. อ่าน error แรกและ stack trace
3. ตรวจ input/state/network ก่อนแก้แบบเดา
4. ลดขอบเขตด้วย pure function หรือ component test
5. เพิ่ม regression test ก่อนหรือพร้อม fix
6. ลบ temporary log และตรวจ flow เดิมซ้ำ

## EAS Preview Build

เพิ่ม profile นี้ใน `eas.json` เดิมจากสัปดาห์ 8 โดยไม่ลบ `development` profile:

```json
{
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal"
    },
    "preview": {
      "distribution": "internal"
    }
  }
}
```

```bash
npx eas-cli@latest build --platform android --profile preview
```

Preview build ใช้แจกทีม/ผู้สอนทดสอบก่อน production และต้องชี้ไป environment สำหรับทดสอบที่ถูกต้อง
